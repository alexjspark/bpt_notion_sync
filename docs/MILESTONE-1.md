# 비즈니스PT admin 사이트와 노션 동기화 1차 완성

기준일: 2026-10-24  
범위: 기존 Windows PC의 단일 담당자 연결, 실제 계정 읽기·미리보기, 별도 승인된 제한적 저장 검증.

이 마일스톤의 “1차 완성”은 아래에서 실증한 범위를 뜻한다. 모든 회원 필드·본문·설문·일정이 일반 버튼으로 자동 저장되는 완성 단계는 아니다.

## 실제 완료한 내용

| 구간 | 실증 결과 |
| --- | --- |
| 기존 연결 | 로그인된 회사 자동화 전용 브라우저와 기존 Notion 서비스 연결을 보존했다. 개인 Chrome 쿠키·비밀번호를 복사하지 않았다. |
| 계정 바인딩 | 정상 회사 응답의 안정적인 계정·트레이너 식별자 쌍을 확인한다. 불일치·검증 불가이면 작업을 보류한다. |
| 일반 버튼 | 실제 UI 버튼 → 서버 요청 → 지속 작업 큐 → worker → 회사/Notion 읽기 → 결과 UI의 미리보기 경로를 완료했다. |
| 관찰한 목록 범위 | 당시 회사 진행 담당 회원 12명과 탈퇴 요청 1건을 읽었다. Notion 28행 중 18행은 유효 UID, 10행은 UID 확인 필요였다. 진행 회원 12명은 유일한 UID 대응을 확인했고 최신 미리보기는 유지 12, 추가 0, 상태변경 0이었다. |
| 기본 정보 | 실제 수집에서 성명·전화·이메일 매핑을 확인했다. 생년월일·성별 전용 상세 수집과 스키마 매핑도 검증했다. 개인정보 값은 이 문서에 포함하지 않는다. |
| 일회 서비스 저장 | 사용자가 해당 필드 편집을 멈춘 조건으로, 전용 UI → 일회 큐 → worker → 제한된 PATCH → 재조회 경로에서 두 회원의 전화·이메일 4칸, 생년월일·성별 4칸을 저장·검증했다. 소모된 실행 승인은 재사용되지 않는다. |
| 별도 수동 보완 | 승인된 회원 연결·단일 신규 생성·상태 변경·첫 수업 날짜·요일/시간·명백한 이름 자리표시자를 지원 Notion 도구로 개별 보완하고 재조회했다. 이 작업들은 일반 worker 저장 완료의 증거가 아니다. |
| 격리 저장 실험 | 가상 TEST 페이지 한 개에서 생성·중복 방지·순차 편집 보존·재조회·복구 가능한 휴지통 정리를 수행했다. 원본 템플릿과 실회원으로 경합 실험하지 않았다. |
| 필수 디버깅 로그 | 실행/요청 ID, 시각, 단계, 결과, 비식별 참조, 제한된 필드·사유·오류코드, 재시도 및 저장/재조회 결과를 구조화했다. 실제 미리보기에서 15개 연결 이벤트를 확인했다. |

관찰 수치는 당시 읽은 계정·진행 필터·목록 구조의 스냅샷이다. 회사 전체 회원, 다른 담당자 또는 향후 변경된 페이지 구조의 전체성까지 보증하지 않는다. UID 없는 행을 이름만으로 연결하거나 미등록으로 단정해 생성하지 않는다.

## 동시 편집 보호의 실제 한계

기존 빈칸 채우기 구현은 최종 읽기 후 PATCH 전 사용자 편집이 발생했을 때 덮어쓰는 문제를 가상 TEST 페이지에서 재현했다. 현재 서비스가 검증한 Notion API에는 원자적 비교 후 쓰기 계약이 없다. 재조회·서버 잠금·사후 비교만으로 Notion UI 편집자와의 마지막 읽기/쓰기 경합을 제거하지 못한다.

일반 MemberInfoStore는 기존 페이지 PATCH를 보내지 않고 보류한다. 이는 안전한 보류이며 “동시 편집 중 저장 통과”가 아니다. 이미 완료한 일회 저장은 사용자의 편집 중단을 전제로 한 더 약한 운영 보장이다. 전역 보호를 끄지 않았으며 추가 실행 승인을 만들지 않았다.

## 남은 연결과 미검증 항목

- 일반 counted-company 미리보기는 아직 memo를 빈 문자열, fixedSlot을 null, survey를 빈 배열로 전달한다. 실제 메모 상세 → 파서 → 보완 계획의 일반 연결이 필요하다.
- 붙여쓴 요일·24시간 표기(예: 일요일13)는 파서와 회귀 테스트에 반영했다. 이 파서 변경은 로컬 코드 검증 완료이며 runtime 재배포·일반 수집 연결 완료를 뜻하지 않는다.
- 기존 수동 일정·본문·상태 및 명시적으로 비운 값의 보존 정책을 유지한다. 기존 빈칸 보완은 명시적인 속성 소유권과 별도 승인/충돌 정책이 필요하다.
- 원문 설문은 개별 읽기 및 합성 파서 계약을 검사했으나, 제출 설문 전체의 일반 worker 수집·저장 경로는 미완성이다. 미제출을 임의 답변으로 채우지 않는다.
- 새 회원 기본 템플릿 생성과 명시적 자리표시자 개인화는 개별 실증했으나 일반 worker의 전체 템플릿·설문 개인화는 미연결이다. 지원되지 않는 버튼 구조와 잘린 본문 내보내기는 완전 검증하지 못했다.
- 반복 일정 계산·탈퇴 요청 정책의 합성/DB 검증과 실제 상태 한 건 보완은 구분한다. 실제 캘린더 생성·동기화와 일반 일정 쓰기 경로는 미완성이다. 탈퇴 요청 때문에 진행 중인 반복 일정을 지우지 않는다.
- 회사 신청일 기준 첫 수업 날짜 해석에는 명시된 월일·요일·2개월 검증 규칙을 사용하며, OT 의미나 기준일이 불명확한 건은 확인한다. 등록일을 일반적으로 신청일로 바꾸지 않는다.
- Notion UID 확인 필요 10행은 자동 연결하지 않는다. 본인 소유라고 확인된 범위와 기술적인 계정·목록 전체성 검증은 별개이다.
- 초기 로그인/연결, 일부 legacy/격리 TEST 세부 경로, 직접 connector 작업 및 과거 실행의 로그는 공통 trace에 모두 연결되지 않았다. 로그는 저장 장애 시 best effort이다.

## 테스트 증거의 해석

- 최근 구조화 로그 작업: 관련 unit/contract 28건, 격리 PostgreSQL integration 35건 통과; 타입 검사와 production build 통과; 실제 계정 읽기 미리보기 1회 완료.
- 최근 붙여쓰기 파서 보완: 관련 member/template 17건 통과(신규 회귀 3건 포함), root TypeScript 통과.
- 위 수치는 서로 다른 변경 범위의 검사 결과다. 합산해 최신 전체 회귀 검사 수나 전체 요구사항 충족률로 제시하지 않는다.
- 합성 provider 기반 E2E, 실제 PostgreSQL integration, 실제 계정 UI 실행을 구분한다. 코드 테스트 통과가 실계정 전체 자동 저장을 보증하지 않는다.
- 개인별 원문·실행 식별자·페이지 링크·화면 증거는 로컬 비공개 기록에 남기며 Git 공개 문서에는 넣지 않는다.

## 운영 상태

일반 수동 버튼은 미리보기 전용이다. 전역 외부 쓰기와 예약 실행은 OFF, 실행 시간은 미설정이다. 이번 마일스톤/커밋 준비로 로그인·권한·키·포트·브라우저 프로필·외부 데이터가 바뀌지 않는다.

새 토큰 입력이나 기존 키 파일 별도 진단을 요구하지 않는다. 이전 거부 명령을 반복하지 않았다. 마지막 worker 진단은 승인 검토에서 정상 인증 로딩을 별도 키 접근으로 해석하여 실행 전 거부됐고, 해당 개별 보완은 지원 connector로 완료했다. 일반 서비스 연결을 재검증할 때는 이 제한을 먼저 명확히 해야 한다.

## Git 인계 상태

사용자가 지정한 원격은 공개 빈 저장소로 확인했다. 최초 작업 폴더에는 .git이 없었다. 소스의 개인 목적지·회원 상수는 비공개 런타임 설정으로 분리했고 테스트는 합성값으로 교체했다. 원본 개인 설정·소스 백업·실행 증거는 로컬에 보존하며 staging에서 제외한다. docs/PORTABLE-CONFIG.md와 docs/LOCAL-COMMIT-PREPARATION.md를 참고한다. 현재 서비스는 재배포하지 않았다.

## 명시적 회사 UID 속성 — 추가 요구사항

회사 UID 열의 표시 문자열을 상세 링크 ID와 독립적으로 대조하는 수집 계약을 추가했다. 문자열 식별자는 앞자리 0을 보존한다. Notion에는 명시적 companyUid binding을 지원하고 신규 페이지 계획에 연결했다. 기존 빈 UID 보완 helper는 해당 속성만 변경하고 동일값 no-op, 다른값 충돌 보류, 미지원 타입 보류 및 불확실 응답 재조회/재전송 금지 계약을 갖는다. 일반 기존 페이지 쓰기 보류 정책은 변경하지 않았다.

실제 회사 진행 목록 12건에서 UID 표시값과 링크가 두 번 일치했고, 본인 Notion의 유일한 대응 페이지 12개를 확인했다. 기존 UID 속성은 number 타입이므로 스키마를 바꾸지 않았다. 현재 관찰한 UID는 숫자로 손실 없이 왕복 가능한지 검증했으며, 앞자리 0 또는 큰 정수처럼 표현 손실이 있으면 쓰지 않는다. 코드 검사는 합성 식별자로 수행했다.

실제 UID 저장 확인은 0건이다. 첫 요청에서 페이지 URL을 page_id로 전달한 형식 문제가 있었고, UID가 여전히 비어 있음을 재조회했다. 수정한 UUID 대상 요청은 자동 승인 검토가 기존 실제 쓰기 OFF 및 불확실 요청 재시도를 이유로 실행 전 거부했다. 추가 쓰기를 중단했고, 다른 대상은 시도하지 않았다. 이 한정 UID 저장 승인과 과거 OFF 지시의 우선관계에 관한 새 관련 근거 없이는 재시도하지 않는다. 실제 UID 값과 개별 페이지 결과는 Git에 포함하지 않는다.

## 이번 커밋 직전 최종 검사

개인 바인딩 분리·목적지 고정·UID 계약·staging 안전 검사를 포함한 관련 합성 회귀 110건이 통과했다. root/web TypeScript와 production web build도 통과했다. 별도의 실제 계정 새 배포/E2E는 하지 않았다. Git index의 선별 201개 파일 검사에서 알려진 개인 바인딩·키 형태·비공개 경로 문제는 발견되지 않았다. 이는 모든 자유 텍스트 개인정보를 완벽히 탐지한다는 보증이 아니다.

## UID 한정 저장 완료 — 추가 승인 후 최신 결과

사용자가 기존 UID 숫자 속성의 확인된 12개 빈칸만 채우는 이번 1회 저장을 명시적으로 승인했다. 회사 UID 열·진행 필터·각 링크와 기존 승인 대상을 최신 재확인하고, 각 Notion 페이지의 부모·어드민 연결·빈 UID를 저장 직전에 다시 확인했다.

공식 Notion connector로 UID 한 속성만 저장했다. 12건 모두 개별 재조회에 성공했고 마지막 목록 조회도 12건 모두 회사 확인값과 일치했다. 저장 12, 재조회 확인 12, 보류 0, 충돌 0, 불확실 응답 0이다. 기존 number 타입은 바꾸지 않았으며 숫자 변환은 현재 확인값이 손실 없이 왕복되는 경우에만 허용했다. 앞자리 0 또는 표현 손실이 있는 식별자는 이 경로에서 보류한다.

각 페이지에서 UID 외 반환 속성과 반환 본문이 같음을 비교했다. 전체 본문 내보내기 완전성까지 보증하지 않는다. 다른 회원·본문·날짜·상태·일정·권한·키는 변경하지 않았다. 이는 일반 worker나 수동 동기화 버튼의 새 자동 쓰기 실증이 아니라 승인된 한정 connector 보완이다. 일회 작업은 완료됐고 재사용하지 않는다. 전역 자동 쓰기와 예약 실행은 계속 OFF다.

위의 최초 저장 0건/거부 기록은 추가 승인 전의 이력이다. 이번 최신 결과가 현재 UID 저장 상태를 나타낸다. 실회원 UID·개별 페이지 링크·비공개 검증 기록은 로컬에만 보존하며 Git 문서에는 넣지 않는다.

## Database password input

The Windows host helper retains masked manual input. An operator may instead explicitly request a fresh password with both approval and generation switches:

```powershell
powershell.exe -NoProfile -File .\scripts\team-windows-database-store.ps1 -OperatorApproved -GenerateRandom
```

Without `-GenerateRandom`, the existing masked prompt is used. Both paths require `-OperatorApproved` on Windows, use the same dedicated DPAPI CurrentUser store and reject an existing target. There is no password argument or alternate output path. The random path generates 32 CSPRNG bytes and converts them to 64 ASCII hexadecimal bytes inside the process. Only DPAPI ciphertext is persisted; plaintext bytes are cleared in `finally`. Buffer clearing is best effort, not a guarantee against process-memory inspection. Never print a helper return value, unseal a store into a terminal, or put a password in an argument, environment variable, log, chat, Git file or deployment manifest.

Creation preserves the restricted current-user directory owner/ACL and reparse-point checks. Existing stores or unexpected directory ownership/permissions require inspection; do not overwrite, rotate, move or loosen permissions automatically. A failed or interrupted creation can leave an unusable ciphertext file; reconcile that exact file before any retry.

## Planned private storage and delivery

| Item | Dedicated location and scope |
| --- | --- |
| Pilot database password | `%LOCALAPPDATA%/TrainerSync/team-pilot/database-password.dpapi`, DPAPI CurrentUser with database-specific entropy |
| Pilot AES/HMAC pair | `%LOCALAPPDATA%/TrainerSync/team-pilot/operator-keys.dpapi`, separate DPAPI CurrentUser store and entropy |
| Named tunnel credential | Planned `C:/ProgramData/TrainerSync/team-pilot/cloudflared/<tunnelUUID>.json`; restrict the directory and file to the chosen Windows operator before use |
| Deployment metadata | Ignored `local-config/` and `.runtime/pilot-plan/<deploymentId>/`; no credential values |

The standard connector needs its tunnel JSON readable at runtime, so restricted filesystem ACLs protect that file; it is not a DPAPI ciphertext file. Its backup must be encrypted. An account-management `cert.pem` has broader rights than a single tunnel credential and requires separately reviewed handling. Do not copy or reuse existing personal credentials.

Use the approved secret-injection helper only after validating the exact container ID, immutable image, role and deployment labels. Database credentials and keys travel through internal pipes and Docker stdin into role-specific tmpfs files, not Docker environment configuration. An uncertain handoff requires metadata review before retry. Restart loses tmpfs files and requires a new verified injection from the same protected stores.

## Initial operator input

After the dedicated empty pilot DB is migrated and the operator count is zero, the approved bootstrap listener binds only `127.0.0.1` for at most ten minutes. The user enters the separate service login, password and label directly in its local form; the password must not be collected in chat or copied from an existing account. A service login uses the allowed lowercase username syntax, not an email address. Cloudflare Access and TrainerSync remain two distinct checks.

The handler validates original Host/Origin and CSRF, rejects Upgrade/CONNECT, and permits one provisioning attempt. It stores a password hash. If submission or its response is uncertain, inspect whether an operator already exists before attempting anything else. Do not repeat a consumed request or expose this bootstrap listener through the tunnel.

## Backup boundary and required pilot-only work

There is no verified operational pilot backup or restore procedure yet. Do not run `scripts/backup.mjs` or `scripts/restore.mjs` for this pilot: they target the existing `trainer-sync-local` stack and `trainer_sync` database.

A pilot backup must be implemented and rehearsed against the exact new pilot container ID/image/deployment labels. It must include a consistent `trainer_sync_pilot` PostgreSQL custom-format dump, the matching encrypted key/password stores, the dedicated tunnel credential in an encrypted backup artifact, and safe metadata identifying source revision, images, schema, config and resource IDs. Do not copy a live PostgreSQL data directory as a verified backup. Stream dump and credential bytes directly to the chosen private encrypted backup destination without terminal output. Record completion, artifact integrity and restore results without values or member content. Git exclusion alone is not access control.

Use a restricted backup subdirectory under the current user's dedicated pilot directory unless a separately reviewed destination is chosen. Keep backups private and apply the same owner/reparse-point/ACL checks. No off-device transfer, public storage, scheduled backup or recovery-key export is configured by this preparation. State the actual last verified snapshot and recovery point; do not imply automatic backup.

Restore only into a fresh, isolated disposable pilot verification database, preserving both the existing service and the running pilot. Verify schema, counts, tenant boundaries and a harmless encrypted fixture with the matching stores. Keep external routes, member writes and schedules disabled during recovery. Sessions, pending jobs and prior approval states require explicit reconciliation before access is restored. A successful dump alone is not a verified backup.

## Recovery limits

DPAPI CurrentUser recovery is limited to the same Windows user with the required Windows identity/profile material still intact. Another Windows user, Windows reinstallation, machine or disk loss, or a lost/damaged user profile is not covered. Copies of the `.dpapi` files alone do not establish cross-machine recovery. Same-user restart/restore and actual production ACL/tmpfs delivery still require physical verification; earlier synthetic tests do not prove them.

If these stores cannot be recovered, encrypted application data may be unrecoverable. Do not replace the master pair or database password and claim recovery. Stop only the recorded new pilot resources, preserve evidence, and agree a recovery or fresh-pilot decision before changing credentials or data. Never prune or use a global `down -v`; preserve existing services, keys, browsers and member data.
